## Case P46: The deployment pipeline is painfully slow and heavy

**Interview prompt.** Hi, let's talk about something that annoys the whole team every day. Our Spring Boot service is packaged as a Docker image, and that image is now about 800 MB. Every time a developer pushes a commit, the CI pipeline needs around 12 minutes just to build it. Developers have started to batch their changes into big pull requests to avoid waiting, which makes reviews harder and releases riskier. Last week a hotfix was delayed because the pipeline was still building. Our registry storage bill is also growing, and pulling the image on a fresh node takes a long time. The tech lead asks you, a new middle-level backend engineer, to look at it. Please walk me through how you would investigate, what you would change, and what you would tell the team.

**Follow-up questions**
1. How did you prove it was the cause? What would you measure before and after your change?
2. What would you monitor afterwards so the problem does not slowly come back?
3. What is the trade-off of your fix, for example for debugging or for build complexity?

**Key vocabulary**
- image size / image layer
- build cache / cache hit / cache miss
- build time (the pipeline takes ~12 minutes)
- base image
- registry (pulling and pushing images)
- cold start of a node
- "shave minutes off the build"
- baseline measurement ("before and after numbers")

## Case M06: The home page key expired and the database went down

**Interview prompt.** Hi, here is an incident from our last big campaign. Our home page data is cached, and it is the most visited page of the whole application. At some point the cache key for the home page expired. At that very moment, around 5,000 requests arrived at the same time, and all of them went to the database. The database was overloaded and crashed. The home page was down, and so were other features that share the same database, so a small cache event became a full outage. When the database came back, the same thing almost happened again. The incident channel exploded with messages, and the manager wants a clear explanation and a plan before the next campaign. You are on call. Please walk me through how you would investigate it and what you would say to the team.

**Follow-up questions**
1. How did you prove it was the cause? What would you look at in the metrics or in a load test?
2. What would you monitor afterwards to catch it before users do?
3. What is the trade-off of your fix, for example for freshness of data or for complexity?

**Key vocabulary**
- cache expiry / TTL (time to live)
- concurrent requests / burst of traffic
- load on the database / connection pool
- outage / cascading failure
- load test / simulate traffic
- peak traffic / campaign
- "single point of failure"
- post-mortem / incident review
