## Case P39: The yearly report export times out

**Interview prompt.** Hi, this one is from our back-office team. Finance has a screen where they can export a report to a file. For a month or a quarter it works fine. But this week the finance lead tried to export the full-year report, and the browser just showed a gateway error after about a minute. She tried three times and got the same thing. Our support engineer checked, and the gateway in front of our service cuts the request at 60 seconds, so the user never gets a file. Finance needs this report for the year-end audit, and they are not happy. The product manager pings you in the channel and asks for an explanation and a plan. Please walk me through how you would approach it.

**Answer frame:** Situation -> What I investigated -> Root cause -> Fix -> How I would prevent it -> What I would tell the team

**Follow-up questions**
1. How did you prove it was the cause? Which metrics, logs or tools would you use?
2. What would you monitor afterwards? Which alert would you set up, and on which number?
3. What is the trade-off of your fix? What could get worse for the user or for the system?

**Key vocabulary**
- gateway timeout (504) / request timeout
- long-running request
- to time out / to cut the connection
- year-end audit
- user experience / "what does the user see?"
- to reproduce the issue
- to walk someone through
- short-term workaround vs. long-term fix

## Case M17: Page 1 is fast, page 5000 is painfully slow

**Interview prompt.** Hi, this one comes from a data-heavy admin tool. A list screen shows records with the usual page navigation. Everyone says it feels great, and the metrics agree: page 1 returns in about 20 milliseconds. Then a support agent had to go through old records for an investigation and jumped far into the list. Page 5000 took around 6 seconds. The same endpoint, the same filters, the same page size; only the page number is different. There are no errors, no locks reported, and the database CPU is not on fire. But the support team now avoids that screen, and one customer's integration that pages through everything is taking forever. The tech lead asks you to look into it and come back with a clear explanation. Please walk me through your approach.

**Answer frame:** Situation -> What I investigated -> Root cause -> Fix -> How I would prevent it -> What I would tell the team

**Follow-up questions**
1. How did you prove it was the cause? Which tools or commands would you use?
2. What would you monitor afterwards? Which alert would you set up, and on which number?
3. What is the trade-off of your fix? What could get worse, for example for the API clients or for the UI?

**Key vocabulary**
- response time / latency (p50, p95, p99)
- "it degrades as the page number grows"
- execution plan / query plan
- slow query log
- the same endpoint behaves differently depending on the input
- API consumers / clients of the API
- to benchmark / to measure before and after
- backward compatibility

**Speaking challenge.** Set a timer for 90 seconds. Explain to a non-technical support lead why page 1 and page 5000 behave so differently, using only what you can observe (no guessing about the cause out loud!), and what you would check first. Then write your full answer below.
