## Case J15: "Duplicate key" crash in the product report

**Interview prompt.** Hi, quick one from the on-call channel. This morning the operations team opened a ticket: the product report page crashed. They sent us a screenshot with an error saying "Duplicate key" and the report did not load at all. This report groups our products by SKU, and it was working fine last week. Nobody changed the report code recently, but the team did import a new batch of product data yesterday. The error message is short and a bit confusing for the business users, and they are asking if the whole product catalog is corrupted. Management wants an update in thirty minutes. You are the engineer on call. Please walk me through how you would handle it.

**Follow-up questions**
1. How did you prove it was the cause? What exactly did you check in the data and in the code?
2. What would you monitor or test afterwards so this does not come back?
3. What is the trade-off of your fix? Could it hide a data quality problem?

**Key vocabulary**
- stack trace / exception message
- uniqueness assumption
- to reproduce the issue with a minimal example
- data quality issue
- to group by a key
- regression test
- to fail fast vs. to fail silently
- to roll out a hotfix

## Case P06: The annotation is there, but no transaction is opened

**Interview prompt.** Hi, this one came from a code review that turned into an incident. A teammate added a transactional annotation to a method that updates several tables, and he was sure it was safe now. In staging, a business error happened in the middle of the update, and the first table stayed changed while the other tables did not. So the data was left half updated. We checked the code and the annotation is definitely present on the method, and the app starts without any warnings. But when we look at the database connection logs, we cannot see any transaction being opened for this flow. The teammate says, "But the annotation is right there!" and the team is now arguing about whether the framework is broken. You are the engineer on call, and the team lead asks you to explain what is happening and how to be sure. Please walk me through it.

**Follow-up questions**
1. How did you prove it was the cause? What logs or tools did you use to see what was really happening?
2. What would you monitor or test afterwards so this does not come back?
3. What is the trade-off of your fix? Would you also change how the team reviews transactional code?

**Key vocabulary**
- transaction boundary
- partial update / inconsistent state
- to roll back on exception
- to enable debug logging for a package
- to verify an assumption with evidence
- integration test against a real database
- code review checklist
- "it works on paper, but not at runtime"
