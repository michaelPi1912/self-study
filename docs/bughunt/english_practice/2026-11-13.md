## Case P01: The order list is slow and the SQL log is huge

**Interview prompt.** Hi, here is something from our on-call channel this week. Support complained that the "Orders" page in the admin panel feels slow. A teammate, Minh, opened it and measured about two seconds of latency for a single page. The page shows 50 orders per page, nothing fancy. He turned on SQL logging in the staging environment, loaded the page once, and counted the statements: 51 SQL queries for one request. The data volume is small, the database server is healthy, and CPU is low. Product is a bit worried, because the next feature adds more columns to this page. Minh asked you to review the case with him. Please walk me through how you would approach it.

**Answer frame:** Situation -> What I investigated -> Root cause -> Fix -> How I would prevent it -> What I would tell the team

**Follow-up questions**
1. How did you prove it was the cause? What exactly would you look at in the logs or in the code?
2. What would you monitor afterwards, so this kind of problem is caught before users complain?
3. What is the trade-off of your fix? Does it change memory use, the shape of the query or the way other developers write code?

**Key vocabulary**
- "the endpoint is slow" / latency vs. throughput
- to enable SQL logging
- number of queries per request
- round trip to the database
- to measure before and after
- to reproduce on staging
- a regression test / a guard in the test suite
- "the page gets slower as the data grows"

## Case P16: Two admins edited the same product, and one change disappeared

**Interview prompt.** Hi, this is a ticket that came from the business side yesterday. Two admins, Hoa and Tuan, opened the edit page of the same product at almost the same time. Hoa changed the price and saved. A minute later Tuan, who had opened the page before Hoa saved, changed the description and saved. Both saves returned a success message, there was no error in the logs, and nobody saw anything strange on screen. But the next morning Hoa noticed that her price change was gone. The product shows the old price and Tuan's new description. This has happened once before, and people just said "someone must have reverted it". The business owner now wants to know whether the system can silently lose data. Please walk me through how you would investigate and what you would answer to the business owner.

**Answer frame:** Situation -> What I investigated -> Root cause -> Fix -> How I would prevent it -> What I would tell the team

**Follow-up questions**
1. How did you prove it was the cause? Can you reproduce it on demand with two browser tabs or a test?
2. What would you monitor afterwards, and what should the user see when two people edit the same record?
3. What is the trade-off of your fix? Think about user experience, performance and how often conflicts really happen.

**Key vocabulary**
- "two users edit the same record at the same time"
- to silently lose data / a silent failure
- "the first change was overwritten"
- to reproduce a race condition
- concurrent modification
- to surface a conflict to the user
- "it only happens under specific timing"
- audit trail / change history

**Speaking challenge.** Set a timer for 90 seconds. Pretend the business owner is listening and does not know Java: explain, in simple English, what went wrong from the user's point of view and how you would make sure it cannot happen silently again. Then write it below.
